# Proposal 0008: thank-yous that add up

**Status:** closed — part 1 implemented in dzq/1.4, part 2 declined · **Author:** DzenQ team, 2026-10-20

Asked: "five thank-yous from Mom and Dad, any mix" — counts that add up
across issuers, which dzq/1.3 could not write.

1. **A repeated key means "any of these", as in any URL query** —
   accepted. `dzq:gratitude?from=<Mom>&from=<Dad>&count=5`. It works the
   same for every key (`from`, `to`, any field). Together with it,
   conditions are read as **form-encoded URL queries**, so ordinary URL
   libraries build and read them; spaces and non-ASCII are also accepted as
   they are (only `%`, `&`, `=`, `+` must be encoded); vectors compare
   decoded values.
2. **A category with its owner** (`category=help@<Mom>`, `*@<Dad>`,
   `from` optional then) — declined. It is a syntax inside a value for one
   field only, adds an exception to "`from` is required", and pairs issuer
   and category in one key, which the proposal itself rejected for `from`.
   Its only use is summing different categories of different people
   (Mom's "help" + Dad's "success"), DzenQ's per-person stamps. If a real
   case appears, a sum over a list of conditions would be general (any
   fields, any types) instead.
