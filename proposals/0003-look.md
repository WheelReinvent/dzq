# Proposal 0003: `look` — how a statement wants to be shown

**Status:** closed — implemented in dzq/1.2 (spec, reference verifier, CLI, vectors); DzenQ core pending · **Target:** dzq/1.2 · **Author:** DzenQ team, 2026-10-20

## Problem

The giver picks how a thank-you or a certificate looks: a gold or navy
blank, a background, a font. DzenQ keeps this as app-only fields (`blank`,
`color` in `dzenq-key/1` and `dzenq-promise/1`). Another app sees nothing of
it, and an unsigned display field could be changed by anyone.

## Proposal

The statement does not describe its look. It **points** to a look, the way
an XML document points to its stylesheet (`<?xml-stylesheet href=…?>`) or a
JSON document to its schema (`$schema`) — and the way a dzq statement
already points to its type with `s`.

A new optional field, **`look`**, in the private content block of every
type:

```json
"c": { "d": "…", "u": "…", "title": "Thank you", "message": "…",
       "look": "dzenq:EKx7…Qm" }
```

`look` = `<source>:<id>`:

- **`<source>`** says **where to ask**: the app or catalogue that publishes
  the look (`dzenq`, `acme`, …), `[a-z0-9-]+`. How a source is reached is
  that source's business; the look/1 spec may add a common way.
- **`<id>`** says **what exactly**: preferably the **SAID of the look
  document**, so whatever the source returns can be checked to be exactly
  the one the giver chose — a source cannot swap it. Until look documents
  exist, `<id>` may be a plain name (`dzenq:gold`).

- A 44-character `<id>` starting with `E` is a SAID; anything else is a
  name.
- It is **signed** with the rest of the content: nobody can change the
  giver's choice.
- It is **private** with the rest of the content: when the statement is
  shown compact, the look is hidden too.
- It is **a hint, never a condition.** A reader that does not know or
  cannot fetch the look shows its default. Validity never depends on it.

What a look document contains — background, colours, fonts, layout, maybe
pictures — is **not** part of this proposal. It will get its own schema
later ("look/1"); until then apps may publish looks in their own format,
identified by SAID.

## Decided

- `look` = `<source>:<id>`: the source says where to ask, the id (a SAID,
  or a name for now) says what exactly.
- The source is always required. There are no shared source-less names.
- A `.dzq` file MAY carry the look document (and the files it uses) under
  `looks/`, each file named by its SAID; a reader checks the SAID before
  using it. Never required. Givers carry their own, custom looks; they
  leave out catalogue looks every app already has. Compact copies made
  for showing never carry a look. This is a new archive entry, so it comes
  with dzq/1.2.

## What changes

- New schema versions for gratitude (1.2.0 / 2.2.0) and certificate (in
  proposal 0002) that allow `look` in the private block. Statements under
  1.0 / 1.1 stay valid and simply have no look.
- Reference CLI: `dzq sign … --look dzenq:gold`; `dzq open` shows it.
- Vectors: a statement with a look (full and compact), a changed look
  (signature breaks), an unknown look (still valid).
- DzenQ: `blank` / `color` map to `look: "dzenq:<blank>"` now, to
  `dzenq:<SAID>` once look documents exist.
